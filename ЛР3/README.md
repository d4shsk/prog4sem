# Лабораторная работа 3. Разработка REST API для отслеживания курсов валют

## Цель работы

Разработать асинхронное веб-приложение на FastAPI с использованием SQLAlchemy и SQLite, которое позволяет:
- регистрировать пользователей;
- хранить список валют и их текущие курсы;
- оформлять и удалять подписки пользователей на валюты;
- обновлять данные о валютах по данным ЦБ РФ.

## Структура проекта

- `main.py` — создание приложения FastAPI, подключение роутеров, инициализация таблиц при старте.
- `database.py` — настройка асинхронного движка SQLAlchemy, фабрики сессий и зависимости `get_db`.
- `models.py` — ORM-модели `User`, `Currency`, `Subscription`.
- `schemas.py` — Pydantic-схемы для пользователей, валют и подписок.
- `cbr_service.py` — загрузка и обновление курсов валют с сайта ЦБ РФ.
- `routers/users.py` — CRUD-операции для пользователей.
- `routers/subscriptions.py` — создание и удаление подписок.
- `routers/currencies.py` — получение списка валют, курса по коду и обновление данных.
- `requirements.txt` — список зависимостей проекта.
- `test_api.py` — интеграционный скрипт для проверки основных сценариев API.
- `currency_app.db` — локальная база данных SQLite.

## Структура базы данных

В приложении реализованы три основные сущности.

### 1. Пользователь (`User`)

- `id` — первичный ключ;
- `username` — уникальное имя пользователя;
- `email` — уникальный email;
- `created_at` — дата и время создания записи.

### 2. Валюта (`Currency`)

- `id` — первичный ключ;
- `code` — уникальный буквенный код валюты (`USD`, `EUR` и т. д.);
- `name` — наименование валюты;
- `rate` — последний сохраненный курс.

### 3. Подписка (`Subscription`)

- `user_id` — внешний ключ на таблицу пользователей;
- `currency_id` — внешний ключ на таблицу валют;
- составной первичный ключ из пары `user_id` и `currency_id`, исключающий дублирование подписок.

Связь между пользователями и валютами реализована по схеме many-to-many через таблицу `subscriptions`.

## Реализованные эндпоинты

### Модуль пользователей

- `POST /users/` — создание пользователя;
- `GET /users/` — получение списка пользователей;
- `GET /users/{user_id}` — получение пользователя по идентификатору вместе со списком подписок;
- `PUT /users/{user_id}` — обновление данных пользователя;
- `DELETE /users/{user_id}` — удаление пользователя.

### Модуль подписок

- `POST /subscriptions/` — подписка пользователя на валюту по `user_id` и `currency_code`;
- `DELETE /subscriptions/` — удаление подписки пользователя на валюту.

### Модуль валют

- `GET /currencies/` — список всех валют, сохраненных в локальной базе данных;
- `POST /currencies/update` — загрузка актуальных данных с сайта ЦБ РФ и обновление локальной таблицы валют;
- `GET /currencies/{currency_code}/rate` — получение текущего курса выбранной валюты.

## Проверка работоспособности

Проверен основной сценарий работы приложения:

1. Получение списка пользователей.
2. Создание нового пользователя.
3. Получение списка валют из базы.
4. Подписка пользователя на валюту.
5. Проверка, что валюта появилась в списке подписок пользователя.
6. Удаление подписки.
7. Удаление созданного пользователя.

Все операции отработали с ожидаемыми HTTP-статусами.

Эндпоинт `POST /currencies/update` зависит от доступа к сайту ЦБ РФ. В текущей среде повторно проверить его не удалось из-за ошибки подключения, но в проекте уже есть база `currency_app.db` с загруженным списком валют.

## Инструкция по запуску

### 1. Установка зависимостей

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Запуск приложения

```bash
python -m uvicorn main:app --reload
```

После запуска документация Swagger будет доступна по адресу:

- `http://127.0.0.1:8000/docs`

### 3. Проверка API

Для запуска тестового сценария можно использовать:

```bash
python test_api.py
```

Для корректной проверки эндпоинта обновления валют требуется доступ к интернету и доступность ресурса ЦБ РФ:

- `https://www.cbr.ru/scripts/XML_daily.asp`
